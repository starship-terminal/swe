# Ported logic

Where each user-facing feature stands on each client is in
[FEATURES.md](../FEATURES.md); the rules that keep both files honest are in
[AGENTS.md](../AGENTS.md#keeping-the-clients-in-step).

Behaviour implemented in two codebases at once: Swift for the Mac app (and
where noted, the iOS app), Python for the hub and web app. A bug in one of
these is the same bug twice by default. A fix that lands on only one side
owes the other the same change; say so in the row's Notes until it is paid.

Transcript mirror ([#1918](https://github.com/starship-terminal/swe/issues/1918)): Both writers read a pruned Claude Code or Codex session's mirror copy into the index, filed under the transcript's own source path, never the copy's: Python in `search_writer._index_copies` (pinned by `tests/test_search_mirror.py`), Swift in `SearchMirror.indexCopies` with `SearchMirror.copiedRows` and the store's `commitFile(drop:adopt:gone:copyMark:)`, `stageMessages`, `discardStaged` and `retire` (pinned by `SearchMirrorTests.swift`, and against rows the real Python writer left for the same steps by `SearchMirrorCrossWriterTests.swift` with `Fixtures/mirror/`). The Swift pass runs on full scans only (`Ledger.scan` with no `recentLimit`), after the live Claude and Codex files, so its live set is that scan's whole enumeration of the ledger's Claude and Codex homes plus, as swe lists them, every `~/.swe/accounts/<vendor>/*/home` on disk that no profile registers (walked for liveness only, `TranscriptMirror.liveInUnlistedHomes`); it walks the mirror once per full scan for both the index and the ledger. Paths: swe records `realpath` forms and the app `resolvingSymlinksInPath` forms; they agree for any home outside `/private` (every real home), and a key from the manifest is used as written. Inputs: the pass's live sources, one walk of `data/transcripts/` (`claude/`, `codex/`, `accounts/<vendor>/<id>/`; `*.jsonl`, hidden names and `subagents/` pruned) and the manifest. Key: a session's identity is `(harness, id)`, the id taken from the file name alone, lower-cased: a Claude file's stem when it is a uuid, a Codex rollout's first uuid (the thread id); a name with no session uuid is its own identity (the source path), so it never stands for another file. The same for live sources, copies (after their source path is known) and `files.path`. Per identity no live source carries: (1) candidates are the copies whose source path is known (manifest `source`, else `transcript_mirror.source_candidates`, the layout inverse, preferring a candidate that has a `files` row) and not on disk (`lstat`); (2) the newest by `(mtime_ns, path)` is used, the rule the listing and reads apply; (3) every row of the identity is fetched once per pass (`files` joined to `sessions` on `agent`, identity of `files.path`); any row at a path on disk ends it (this is also what keeps a live session the pass does not enumerate safe); (4) if a row covers the copy (state `current`, a session, offset not -1, `mtime_ms` and `size_bytes` at least the copy's), nothing is read, and the identity's other rows that this keeper dominates (its `mtime_ms` and size at least theirs) are deleted in one transaction fenced on the keeper and each row (`session_row_id, byte_offset, mtime_ms`) with each path re-checked gone; (4b) a row under the source path that reads current for the copy's stat (`read_need`, a copy that held no session) ends it, nothing read; (5) if any row is not dominated by the copy, it ends; (6) otherwise the copy is read whole under the source path. A read that commits in pieces (over the 32 MiB text budget) stages them on a session already visible for the identity (the source path's row's, else another row's), touching no `files` row, so search sees one session holding at least what it held; the final commit mints the new session, moves the staged messages to it by the exact ids the read wrote (never "every message past an id": the Mac writer may append to the host meanwhile), writes the `files` row (the copy's ino, `mtime_ms` and size) and deletes the identity's other rows, all fenced the same way with the source path and every deleted row's path re-checked gone. A read that fails takes back exactly the messages it staged; a kill leaves them on a session the next whole read deletes. Every commit from a copy records `meta` `mirror_copy:<path>` = `"<agent> <session row id>"`, and any other commit for that path deletes the key. Live side: when a live file of an identity is read, or is already current, the identity's rows whose mark still names their session, under other paths that are gone, are deleted in that same commit (or a fenced commit of their own when the live file needs no read); a row without a mark, one the index read from a live file, is never deleted this way. Nothing else removes a row, so a lost manifest or a missing copy changes nothing; a deliberate purge unlinks the copies, then calls `search_writer.forget_session(home, harness, session_id, source_path=None)`, which deletes the identity's rows under gone paths, each only if unchanged and still gone inside the delete's transaction (`source_path` names a transcript whose file name has no session uuid). Ledger: events recorded for a pruned session stay (the ledger deletes nothing when a log goes). Swift's full scan also reads a copy for usage it never recorded: only for a session no live file carries, whose source is gone and whose source cursor does not already prove it read the copy's bytes (same size and mtime, read to the end, head, middle and tail samples matching the copy; a bare offset proves nothing about a rewritten file), under the copy's own cursor so it is read once, its events filed under the copy's harness home; events keep their content keys, so a line the ledger already holds upserts onto its own row and nothing is counted twice (`LedgerMirrorTests.swift`). Owed by Python: the same copy read in `src/swe/ledger/` (today the hub's ledger loses usage it never scanned before a pruning) |
