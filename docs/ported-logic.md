# Ported logic

Where each user-facing feature stands on each client is in
[FEATURES.md](../FEATURES.md); the rules that keep both files honest are in
[AGENTS.md](../AGENTS.md#keeping-the-clients-in-step).

Behaviour implemented in two codebases at once: Swift for the Mac app (and
where noted, the iOS app), Python for the hub and web app. A bug in one of
these is the same bug twice by default. A fix that lands on only one side
owes the other the same change; say so in the row's Notes until it is paid.

Transcript mirror ([#1918](https://github.com/starship-terminal/swe/issues/1918)): Python reads a pruned Claude Code or Codex session's mirror copy into the index, filed under the transcript's own source path, never the copy's. The Swift writer needs no change to stay compatible: it only reads files its roots enumerate, so it never touches a row for a gone path, and a source restored to that path reads as the same row (current when mtime and size match, else replaced in place). Owed by Swift, for a Mac that runs no Python pass to search copies: the same rule (`search_writer._index_copies`, pinned by `tests/test_search_mirror.py`). Inputs: the pass's live sources, one walk of `data/transcripts/` (`claude/`, `codex/`, `accounts/<vendor>/<id>/`; `*.jsonl`, hidden names and `subagents/` pruned) and the manifest. Key: a session's identity is `(harness, id)`, the id taken from the file name alone, lower-cased: a Claude file's stem when it is a uuid, a Codex rollout's first uuid (the thread id); a name with no session uuid is its own identity (the source path), so it never stands for another file. The same for live sources, copies (after their source path is known) and `files.path`. Per identity no live source carries: (1) candidates are the copies whose source path is known (manifest `source`, else `transcript_mirror.source_candidates`, the layout inverse, preferring a candidate that has a `files` row) and not on disk (`lstat`); (2) the newest by `(mtime_ns, path)` is used, the rule the listing and reads apply; (3) its `files` row under the source path ends it if that row covers the copy (state `current`, a session, offset not -1, `mtime_ms` and `size_bytes` at least the copy's) or reads current; (4) otherwise every row of the identity is fetched once per pass (`files` joined to `sessions` on `agent`, identity of `files.path`), and the copy is left alone when any of them sits at a path on disk, covers the copy, or is not dominated by it (dominated: copy `mtime_ms` and size at least the row's `mtime_ms` and `size_bytes`; a row under the source path counts too); (5) otherwise the copy is read whole under the source path (the `files` row records the copy's ino, `mtime_ms` and size; `sessions.file_path` is the source path), and the identity's rows under other paths are deleted with their sessions in the final commit, each fenced on `(session_row_id, byte_offset, mtime_ms)`. Nothing else removes a row, so a lost manifest or a missing copy changes nothing; a deliberate purge calls `search_writer.forget_session` after unlinking the copies. `Ledger.scan` ignores the mirror (its rows already outlive a pruned log) |
