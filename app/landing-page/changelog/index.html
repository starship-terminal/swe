Unreleased

Added

  • Restore and purge mirrored transcripts, and see the mirror in swe doctor. swe session restore <N|id> puts a mirrored session's copy back where Claude Code or Codex kept it (the project folder, the dated or archived Codex path, or an account home), so it lists as live again and swe session use resumes it. It takes the # from swe session, the session id or a Codex thread id, restores the copy the listing shows, recreates a deleted project folder, and refuses when any file is at that path: it never overwrites a transcript. swe session mirror --purge=<id> (a session id or Codex thread id, never a #) is the one way to delete a mirror copy: for a session whose transcript the harness already deleted, it lists every file it will remove (the session's copies, their .shrunk-* backups) and asks first (--yes skips the prompt), then drops their manifest entries. It refuses a live session and any file that is a symlink or behind one. swe has no session delete command, so there is no --purge on one; without a purge a mirrored session keeps listing. swe doctor gains a Transcript mirror section: on or off, copies and bytes, orphans, the last pass, copies the manifest does not know, entries with no copy and temp files a crash left; swe session mirror --sweep-tmp removes those temp files, and a crashed restore's own beside its target, once they are a day old. The hub now streams a mirrored session's chat to the web and iOS clients from the copy with the same detail as a live chat (thinking, tools, record times), read once and never tailed; before, it fell back to the plainer report reader and re-read the copy on a timer (#1918).

  • Transcript mirror: sessions survive the harnesses' 30-day pruning. Claude Code and Codex delete transcripts after about 30 days. swe now copies each one into ~/.swe/data/transcripts/ while it exists (on by default; swe session mirror --off stops it) and never deletes a copy: not when its source disappears, not to save space. On macOS a copy is an APFS clone (clonefile), so a 13 GB projects folder costs almost no extra disk and no I/O; other systems stream it. swe session mirror runs a pass and --json reports cloned, copied, unchanged and orphaned counts and bytes; the hub's loop and swe session index run one too, from the same walk the search index uses. A session whose harness deleted the transcript stays in swe session (and --json, as mirrored: true, with no resume command), and swe report and the transcript view read it from the copy. Search is unchanged: the mirror writes no index rows. Searching copies the index never read and the Mac app's side are follow-ups (#1918).

  • The Mac Hooks page counts what each hook did. Every script on the timeline shows its fires, blocks and block rate for the last 24 hours, 7 days (default) or 30 days, picked at the top right of the card and remembered; a hook that blocked reads in red, and a rate under 1% reads "<1%" so it never shows "0%" beside a block. Counts add up every harness that runs the script. Opening a hook adds Fires, Blocks and Last block tiles, its top reasons and its five latest runs to the side panel, or "No runs in the last 7 days." when it had none. The numbers load with the page, the picker and Refresh, never on a timer; an swe from before swe hooks stats shows dashes and the page works as before. Which runs are which script's is now decided by the file that ran, not by its name, once in swe for the CLI, the web page and the app: the shim logs the shared script it ran (a new script field in each log line; record called by a hook logs the running program), transcript commands are resolved the way swe hooks list resolves them (quoted paths with spaces, $HOME, symlinks, a generated wrapper to its shared script), and swe hooks stats --json rows carry source_paths (the swe hooks list rows they belong to) and scripts. So a shim run and its transcript copy count once, a directory hook counts every declared executable and nothing its undeclared helpers ran, two files with one basename never share numbers, and a run swe cannot attribute (an old log line whose name two scripts share) marks those rows uncertain, which both pages show as dashes. swe hooks stats --sum-harnesses folds every harness and every name into one row per script before the five-reason cap, --source=<path> on stats and log picks a hook by its list source_path, and --hook= / swe hooks log <name> take a name exactly as it was logged (claude-plugin/on-stop) or the list name (bundle). The web Hooks page joins on source_paths too, and its list rows no longer carry stats_keys. Part of #1888.

  • The web Hooks page shows how often each hook fires and blocks. Every hook row gains Fires, Blocks and Rate columns (every harness's runs added up) under a picker for the last 24 hours, 7 days (the default) or 30 days, which the browser remembers. The hook's own page gains a Runs card: Fires, Blocks and Last block tiles, the top reasons and the five newest runs, or "No runs in the last 7 days." The numbers come from the same read as swe hooks stats --json and swe hooks log --json, served by GET /v1/app/hooks?stats=24h|7d|30d. That read backfills from Claude Code transcripts and can take seconds, so a background thread runs it and the page paints its list first and fills the columns in when they arrive; while they load they are placeholders, and if the read fails they show dashes and the rest of the page works (#1888).

  • swe hooks stats and swe hooks log show what each hook did. The shared-hook shim now appends one line per run to ~/.swe/cache/hooks/events.jsonl (5 MiB, one rotated copy, never sent or committed): hook, harness, event, session, repo and branch, block/warn/allow/error, the first line of the hook's message and its duration, plus stop_hook_active so a Stop block followed by an accepted rewrite reads apart from a plain allow. Logging fails open and SWE_HOOK_LOG=0 turns it off; run swe hooks sync once to refresh the shim. swe hooks stats [--since=7d] [--hook=<name>] [--harness=<h>] [--repo=<path>] [--json] prints fires, blocks, block rate and top reasons per hook, and swe hooks log <name> the recent runs. Claude Code history from before the log is recovered from its transcripts and merged without double counting (--no-backfill skips it). The Mac and web Hooks pages are still to come. Part of #1888.

  • Cursor personal plugin controls. SWE reads account state instead of guessing from downloaded folders, adds on/off for unconfigured, unpinned personal plugins and personal removal, and keeps team-controlled plugins read-only. Protected credentials and failed API reads keep cache state unknown.

  • Devin and OpenCode plugin controls. Devin resolved installs can be removed through its native CLI. OpenCode global file plugins can be suspended into SWE storage, restored, imported, and removed. Controls are available on Mac, web and CLI; Devin has no per-plugin toggle, and OpenCode package/project controls remain unsupported.

  • swe worktree (alias swe wt) manages git worktrees across repos. swe wt list lists every linked worktree in the current repo, or with --all in every repo swe knows (worktree.roots in config, swe gh mirrors, ~/.swe/worktrees, ~/.swe/accounts/*/*/home/worktrees), with its PR, last commit, du size and the space in rebuildable folders. States come from the PR, since squash merges defeat git merge-base --is-ancestor; when gh cannot answer a worktree is unknown and never removed. show, add (a branch, a new branch or a PR's head), remove, lock, unlock and move handle one worktree; every command takes --json and the same calls are a Python API in swe.worktrees, pinned for the coming Mac and web Worktrees pages. swe wt prune is a dry run until --yes, removes only merged-clean worktrees through git worktree remove --force (plus merged-dirty with --include=merged-dirty and a yes each), re-reads each state right before removing, keeps branches unless --delete-branches, reports freed space measured on the volume and logs to ~/.swe/logs/worktree/. --branch=<name> and --auto (per-repo auto_prune in config) are for post-merge hooks. swe wt slim deletes ignored .venv, node_modules, build and similar folders in unmerged worktrees. scripts/reaper.sh is now a thin wrapper over swe wt prune and swe wt slim; it no longer prunes build folders in the main checkout. Closes #1909.

  • Plugins are managed from SWE. The Mac and web plugin lists hide marketplace-only entries and missing installs. Import to SWE copies installed plugin files into ~/.swe/plugins without changing a harness or overwriting SWE files. The Mac table renders rows lazily and precomputes its local inventory and action menus.

  • Harness-only skills adopt into the shared tree. swe init (skip with --no-adopt) and swe skills adopt [<name>|--all] move a skill that only lives in a harness's real skills folder into ~/.swe/skills verbatim, leave a per-skill link in the donor root so that harness sees no change, record the donor in skill_links.json's adopted_from, and mark the skill off for every other root — a whole-root link converts to an except selection — so nothing new appears anywhere. Same-named copies never merge: the first root in registry order donates, identical ones fold into links, divergent ones stay and flag conflict on the shared row in swe skills --json. swe skills remove <name> deletes a shared skill plus every link into it and purges its records so a later adopt cannot resurrect it. swe init --check previews the pass and reports it as skills_adoption. Closes #1882.

  • AGENTS.md page: drafts list and compiled size (macOS app). A "Drafts (N)" menu beside the Edit/Compile tabs lists every chapter with unsaved changes and jumps to it; it appears only while there are drafts. The View AGENTS.md button and popup now show the generated file's size in KiB as last built, per harness output on the Compile tab. Part of #1894.

  • AGENTS.md Compile tab: a KiB column and one harness dropdown (macOS app). The Include tree gains a KiB column: each chapter file's size on disk with one decimal, each folder the sum of its checked files, and a Total row while one harness is picked. The row of harness chips becomes a multi-select dropdown (All harnesses, the harness name, or "N harnesses") that keeps each logo and link-state dot in its menu; picking several narrows the Order matrix to those harnesses. The "Shared ~/.swe/AGENTS.md: N chapters" summary line under the harness bar is gone. Closes #1893.

  • The AGENTS.md chapter outline has search, keyboard navigation and drag handles (Mac). A Filter chapters field above the Edit tab's outline matches file names and paths and keeps matching files' folders open; clearing it restores your folders and selection. With the outline focused, Up/Down move between rows, Left/Right collapse, expand or climb to the parent folder, and Return opens a chapter, while the text editor keeps its arrow keys. Rows show a grip on hover, a dragged chapter shows an insertion line, and the folder it will land in is outlined. Part of #1894.

  • AGENTS.md: resizable chapter pane and editor focus mode. On the macOS app's Edit tab, drag the divider between the chapter outline and the editor (double-click resets; the width persists, with minimums that grow with text zoom). Focus mode (⇧⌘E or the button in the page row) folds away the outline and the harness strip; the file name, Unsaved dot, Save and View AGENTS.md stay visible. Part of #1894.

  • Devin is a verified MCP sync target. swe mcp sync writes ~/.config/devin/mcp_config.json (Devin CLI v3000.3+ / MCP configuration docs), not the unverified ~/.devin/mcp.json guess. swe mcp list shows a Devin column once the harness is registered.

  • Harness targets beside the chapter editor (Mac). The AGENTS.md page's Edit tab shows a Targets strip above the open chapter: a logo and name chip per harness, bright when it gets the chapter, a line saying why (no rule, an only or except rule in targets.json, or off in index.txt), and a folder line when every chapter in its folder shares the same targets. Clicking a chip or the In AGENTS.md checkbox writes the same index.txt and targets.json edits as the Compile tab, through the same save queue, so both tabs always agree. Compilation rules are unchanged.

Changed

  • FEATURES.md is now a feature inventory. The cross-client matrix became ## <Area> sections with one line per feature per surface (CLI, web, iOS, macOS, API or job), each giving its status (stable, beta or planned), entry point and the tests behind it, so QA checks can map onto it. Each client's notes and what it still owes moved onto its own line, and tests/test_features_inventory.py checks the line format and that every test path exists. The table of logic ported between Swift and Python moved to docs/ported-logic.md, and the README links FEATURES.md.

  • Mac Accounts now groups accounts into horizontally scrolling provider columns. Narrow cards keep the plan visible, with usage rings and settings beneath. Click a card to smoothly expand its readings; drag provider columns horizontally to save their order. Expanded cards put settings beside the launch buttons and wrap their status text.

  • Mac Codex account cards show monthly credits used and the credit limit beneath the usage bars when the workspace returns those amounts.

Removed

  • The in-repo MCP gateway daemon. swe mcp gateway serve, install and uninstall are gone: the gateway lives in the standalone warp-gate package (repo starship-terminal/warp-gate, installed as the LaunchAgent com.starship-terminal.warp-gate by warp-gate install), serving the identical http://127.0.0.1:8478/mcp/<name> contract. swe mcp gateway keeps share, unshare and status — status still reports a machine's installed agent, including a retired com.cwenlong.swe.mcp-gateway/com.cwenlong.quiver.mcp-gateway one left over from an older install — and swe mcp sync still writes the gateway URL for "shared": true servers while gateway.enabled is set. A stale agent left by an old swe keeps no home here: bootout and delete its plist (launchctl bootout gui/$UID/<label>, then remove ~/Library/LaunchAgents/<label>.plist), then warp-gate install.

Security

  • A task link can no longer point the hub's gh at any repo. POST /v1/sessions/{key}/task stored a GitHub task for whatever repo the client named, and every GET /v1/tasks then ran gh against it as the hub owner. A new link to a repo the hub hasn't pinned now answers 422 not_pinned. Tasks already stored keep their links and keep refreshing after their repo is unpinned.

  • The hub's session journals are private to your account. Every prompt, reply and tool call a remote session sees is journaled under ~/.swe/data/remote/journal/, which was created 0755 with 0644 files, so any other local account could read them. The folder is now 0700 (an existing one is tightened) and its files 0600.

  • A pairing poll's secret no longer travels in the URL. The web app and the iPhone app polled /v1/pair/request/<id>?secret=…, so the secret that collects a new device's credential could land in proxy and access logs. Both now send it in an X-Pair-Secret header; the hub still reads ?secret= for iPhone builds already out.

  • An Open in session prompt no longer carries a stranger's PR text. Anyone can open a pull request on a public repo, and its title, body and failing check names (which a fork's own workflow can name) went word for word into the first prompt of the agent reviewing it. The brief now follows the resolve prompt's rule: it quotes the title and body line by line behind a note that they are untrusted data, only when the author's author_association is OWNER, MEMBER or COLLABORATOR, and otherwise says in one line that they were left out. Failing check names are always quoted, and the web's Open in session sheet no longer puts the title in the prompt it prefills. The hub's PR detail gains association.

  • A resolve prompt no longer carries strangers' comments. Anyone can comment on a public issue, and every comment went word for word into the first prompt of the agent resolving it. The prompt now quotes the issue's title, body and comments line by line behind a note that they are untrusted data the agent must not take instructions from, keeps only comments whose authorAssociation is OWNER, MEMBER or COLLABORATOR, and replaces the rest with "N comments from others, not included". Every client prefills the hub's suggested_prompt, so the Mac, iPhone and web resolve sheets all get the new prompt; issue comments in --json gain association.

Fixed

  • The Mac app recognises sessions in starship-terminal/swe worktrees again. After the rebrand, the issue Resolve dialog stopped matching checkouts and starship-terminal__swe-… worktrees to this repo, so it no longer preselected the harness last used there. Folders made under the old c-wenlong owner or the quiver name still match.

  • Models speed and latency survive Artificial Analysis dropping performance on Dec 10, 2026. The Mac app reads output speed, time to first token and time to first answer token from performance_v3 (means) first, then the old performance medians, then the legacy top-level keys, so the Models page columns stay filled once performance goes null.

  • swe init saves the harness executable even when it is off PATH. Registering ~/.vibe/skills before vibe was installed stored an empty command under mistral-vibe, so swe list kept reporting the harness as not installed after vibe appeared, because it looked for a binary named mistral-vibe. Init now takes the command from the built-in catalog for the canonical key (vibe, qwen, droid), and a command already set in harness.json is never overwritten. Follow-up to #1916.

  • A collapsed sidebar no longer blocks clicks beside the rail (Mac). The rail kept its icons laid out at the expanded width, and .clipped() hides that overflow without removing its hit area, so it swallowed clicks up to the expanded width, such as the AGENTS.md Edit tab. The list now takes clicks only over its visible width, and the title bar reader no longer takes clicks. Closes #1892.

  • Codex education monthly usage reads the workspace billing allowance when the standard usage response omits it, showing both the percentage and credit amounts.

  • Installed plugins can be switched and removed before import. Claude Code and Codex on/off and uninstall controls work for harness-owned plugins. The Mac row and per-harness action menus use themed popovers, with confirmed removal from one or all harnesses; import remains separate for SWE file ownership.

  • AGENTS.md editor header no longer wraps at narrow widths (Mac). In a 900 pt window the Edit tab's Revert, Save and Close buttons wrapped mid-word ("Rever t"). A narrow editor now shows them as icons (named in the tooltip and to VoiceOver) and the Unsaved marker as a dot, and the Chapters heading stays whole; wider windows keep the words.

  • The Mac app no longer offers to trash a skill's SKILL.md by itself. A skill's Contents card put a trash button on its main SKILL.md (and on each skill folder's SKILL.md in a plugin), though a skill can't work without it. Those rows now have none; every other file keeps its button, and removing the whole skill stays its own action.

  • Devin's ACP approvals say what they run. devin acp sends a permission request with only the tool call's id, so the card read "permission requested". It now shows the title and command from the tool call Devin announced earlier, such as "Ran rm" with rm hello.txt.

  • A skills root that links to itself no longer crashes the skills commands on Python 3.11 and 3.12. Before Python 3.13, resolve() raises RuntimeError on a symlink loop, and the skills root scan and root lookups only caught OSError, so a ~/.codex/skills pointing at itself ended swe skills <filter>, swe skills tree, swe skills link and swe skills move in a traceback. A looped root is now handled like a dangling one: swe skills link replaces it, a path argument skips it, and move names it in an error. Linking a root to a target that loops is refused before the old link is removed, on every Python version.

  • One unreadable log no longer empties swe models for its harness. The model tally read each Claude, Codex and Freebuff log with the locale's strict decoder and no error handling, so a single file with a stray non-UTF-8 byte, or one it lacked permission to open, raised out of that harness's whole scan and dropped every model count it had gathered. Each log is now read as UTF-8 with bad bytes replaced, and a file that can't be opened counts nothing on its own.

  • A report no longer lists a follow-up it refused to create. When the report writer suggested a new follow-up whose evidence was not a list, the pipeline dropped the suggestion with a warning but had already put its id in the report manifest's follow_up_ids, naming a follow-up that never reached the ledger. The evidence check now runs before the id is recorded.

  • A second launch in a folder no longer strands both. Adoption tells a new session apart only by harness, folder and start time, so two launches of one harness waiting in one folder each saw both transcripts and neither was ever adopted. A launch while another is still starting in that folder is now refused (409 launch_pending, naming the waiting tmux pane), so the first is adopted as before.

  • Messages typed into a tmux session can't drive the TUI. Text the hub sends to a tmux pane now loses C0 control characters other than tab and newline (an ESC or ^C in a message cancelled turns or picked menu rows), and text with line breaks goes in as one bracketed paste instead of one Enter per line.

  • Issue resolves work on swe/issue-<n>. swe gh issue worktree and the hub's Resolve with agent still cut quiver/issue-<n>. New resolves branch swe/issue-<n>; a checkout or branch a resolve left under the old name is resumed on it (and the prompt names it), and the Tasks rows still find the PR such a branch opened, so no work in flight is orphaned. The Mac, iPhone and web sheets' fallback label says swe/issue-<n> too.

  • swe's tmux panes are named swe-…. Sessions the hub runs under tmux were still named qv-<slug>. New panes are swe-<slug>, so tmux attach -t swe-… is what the web chip, the Run in terminal button and the docs give. Panes a hub started before the upgrade keep their qv- name: the hub still writes to them, a satellite's rows still carry them, and a launch never starts a second pane beside one.

  • Linux hubs and satellites run as swe-remote-*.service. swe remote serve --install and swe remote agent --install still wrote quiver-remote-hub.service and quiver-remote-agent.service. They now write swe-remote-hub.service and swe-remote-agent.service, and once the new unit has started they stop, disable and remove the old one, so a machine never runs two hubs after the upgrade. --uninstall removes both names, --status and swe remote setup still see an old unit that is all a machine has, and scripts/install.sh restarts whichever is active.

  • SWE.app ships the licences of the Python and Sparkle it carries. The bundle held only SWE's own licence and CPython's and OpenSSL's texts. Contents/Resources/Licenses/ now has Sparkle's LICENSE and the licence of each library the bundled Python links (libffi, Expat, SQLite, xz, bzip2, mpdecimal, libuuid, OpenSSL, zlib, libedit, ncurses), and the build stops if one is missing. app/mac/THIRD_PARTY_NOTICES.md lists them all and now names every colour harness logo.

  • The web app installs as an app and respects the notch. Its manifest now says display: "standalone" and carries an id, and its background and theme colours follow the light default and the dark scheme (color_scheme_dark). The page declares one theme-color per scheme, and a Light or Dark picked in Settings overrides both, so the status bar matches the page. The sidebar, pages and chat composer pad themselves by env(safe-area-inset-*), since the viewport covers the whole screen.

  • Phone SSH keys carry the swe-remote: tag. The hub still tagged the ~/.ssh/authorized_keys lines it manages quiver-remote:<device id>. New lines say swe-remote:<device id>; a line under the old tag still counts as the hub's (and as installed), and the next rewrite swaps it for the new one, so a revoke after the upgrade still removes it.

  • swe harness discover --json --apply NAME answers in JSON when NAME is not a new match. It printed red text, which the app could not decode. It now prints the usual document with applied.refused and the name under applied.skipped, and exits 1.

  • The web app's model search and price edits no longer wait on the daily price download. The LiteLLM price list was fetched while holding the lock every catalog read and price save takes, so a slow network stalled the Models search and the Pricing page. The fetch now runs outside it, and a download cut short counts as tried for the day.

  • A model or effort switch is no longer typed into a TUI that can't take it. On a tmux session the hub typed /model <v> or /effort <v> into any harness's pane, so opencode or codex (for effort) got the line as a prompt to the model. It now refuses with unsupported_control unless the harness's TUI is known to run the command, the rule the session's model_modes and a launch already follow.

  • A status feed with a NaN or out-of-range time no longer blanks the web Status page. Python's JSON reader takes NaN, Infinity and 1e400, and the incident time went back out as bare NaN, which the browser refuses to parse. Such a time now reads as unknown, as it does in the Mac app.

  • A late approval tap can no longer answer the next terminal prompt. Once a prompt was answered at the terminal, its request id stopped being checked, so a phone's delayed tap on it could answer the next prompt the agent showed before the hub had named it. A replaced or cleared id is now refused. An approval's key walk also shares the pane's write lock, so a message steered in at the same moment can't land between its arrow keys.

  • One odd message from codex no longer stalls a Codex session. An app-server message the hub couldn't read (an approval with list params, an unhashable id) ended the reader while codex kept running, so every later send waited its full 60 s and failed until a detach. The reader now skips such a message, and a server whose reader did die is replaced on the next send.

  • Archiving Qwen Code stops its shared hooks, and its hook settings count. The hook contract table keyed Qwen Code as qwen, its command, while harness.json calls it qwen-code. Archiving qwen-code still deployed shared-hook wrappers into ~/.qwen/hooks, and a capabilities.hooks entry on qwen-code was never read. The row is now qwen-code, and swe init (or swe hooks sync) moves an existing ~/.swe/hooks/qwen/ to hooks/qwen-code/ once and relinks it; a hub that already has both folders is told to merge them by hand. The move waits while a link to the old folder could not be relinked (qwen-code archived, or the link in .linkignore) or a settings file names the old folder, so no hook stops running.

  • swe skills new says when it had to make ~/.swe/skills. create() promised to report whether it made the hub skills root but always answered no, so a skill written into a brand-new root (one no harness links to yet) printed only "Created". It now adds a line saying to run swe init to link the root into your harnesses.

  • Qwen Code sessions get @ file references for attachments again. The hub's attachment fallback table keyed Qwen Code as qwen, its command, but sessions carry the registry id qwen-code, so a file sent from a phone arrived as an [Attached file: …] line instead of an @ reference.

  • A satellite's malformed push no longer breaks the hub's routes. /v1/agent/register answered 500 when machine was not an object; an uploaded event whose data was not an object failed its whole batch, which the agent then resent forever, journaling the good events again; a "/" menu push with the wrong shapes turned that satellite's menu route into a 500; and NaN/Infinity (or 1e400) in any request body was stored and served back, which no client's JSON parser accepts. Each is now a 422, a skipped event, a skipped row or a 400.

  • An approval resolved without a request id now kills its ntfy buttons. The hub clears every pending approval on such a resolve, but the notification tokens were retired only by exact request id, so the buttons of the cleared prompts stayed spendable until they expired and could answer the next prompt on the session.

  • An opencode approval's request id can no longer reach another serve route. The hub put the client's request id into the opencode serve URL as typed, so an id like ../../<session>/abort posted to a different route; ids and session ids are now one quoted path segment.

  • A wildcard hub bind no longer turns off the Host check, and a second swe remote serve on a taken port no longer disturbs the running hub. --host=0.0.0.0 --unsafe-bind-any left the hub's allowed Host names empty, which lets any Host through, so a page that rebound its name to the hub could pass as the owner's own tailnet device; :: was not even read as a wildcard. Both now answer this node's loopback, hostname and tailnet names, plus any IP address on the hub's port (a LAN pairing link), since a rebound page always arrives under its own domain name. serve also binds before it starts the hub's loops, so a copy that can't get the port exits before it registers the machine, settles kept sessions or retires ntfy credentials under the running hub.

  • Codex sessions were undercounted when codex ran subagents. parse_codex dropped every thread whose store preview was empty, treating it as opened and never typed into — but codex also leaves preview blank on spawned threads (subagents, automations) no matter how much work they did. On a machine running codex's multi-agent feature that hid almost every session. A thread now drops only when preview is empty and tokens_used is zero — the store's own record that it never ran — and kept spawned threads are titled from agent_path's leaf or agent_nickname rather than their transcript's injected-context first line. swe session and the session counts on swe list also pick up ~/.codex/archived_sessions/ now: archiving a thread moves its rollout there, and an archived session still ran.

  • swe init no longer re-asks about a harness it already registered. A skills root discovered under an aliased label (~/.vibe/skills is "vibe", the binary behind mistral-vibe) was filed in harness.json under that label, while every "is this root known?" check translates the label to the canonical registry key — so the entry never matched and the "New skills folders found" picker came back on every run, most visibly inside darwin-rebuild activations. Registration now writes the canonical key and absorbs a stale label-keyed entry, and the known, archived and disabled-name checks all count a key's canonical name too, so an entry an older init filed as vibe still reads as registered.

Added

  • Devin free-model limit status. Accounts and the Mac menu bar show a reached free-model limit and its reset time from Devin's CLI logs, separately from daily and weekly paid quota. The CLI marks an active block with free:blocked; web and iPhone cards show it too. Without an active observed block, the cards say Unknown because Devin does not report a remaining free-model percentage.

  • Remote: ntfy approval buttons can no longer switch off later approvals. The owner's own tailnet devices get in without pairing, and Revoke refused their tailnet:<node> ids, so a lost phone signed in to the owner's Tailscale account walked straight back in through Safari.   • Mac app: the fan helper is checked against SWE's own signature before it runs as root. The one-time install copied SWE.app/Contents/MacOS/SWEFanHelper to /Library/PrivilegedHelperTools and only checked that the copy matched a hash taken before the password prompt. The bundle is user-writable, so anything running as the user could patch the helper beforehand and have it run as root once the user typed their password.   • Mac app: the fan helper only takes requests from SWE itself, checked by its code signature. The running root helper held the fans for any request whose owner was a live process named SWE, so a program called /tmp/SWE qualified. The install now pins the installing app's signature in the launchd job (--owner-team <team> --owner-identifier <id> for a team-signed build, since the team also signs the Python bundled for swe; --owner-cdhash <hash> for an ad-hoc one), and the helper checks each request's owner against it through its audit token and SecCodeCheckValidity, keeping the answer per process (pid and pid version) so a reused pid is checked afresh. A job without a valid pin starts nothing. The helper is now version 4 and writes its version into /var/run/com.cwenlong.swe.fan.json.   • Remote: a local process can no longer claim the owner's tailnet identity. Behind tailscale serve the hub read the client from X-Forwarded-For on every loopback connection, so any process on the hub machine, another user's included, could name the owner's phone and get owner powers (launch agents, approve pair requests, read API keys). It now believes the header only when the OS places the connection's far end in the Tailscale daemon: a root-owned socket in /proc/net/tcp on Linux, a root process or a binary in a root-owned /Applications/Tailscale.app per netstat -anv on macOS. Anyone else is read as a loopback client with no tailnet identity. The hub machine's own tailnet node also stops counting as the owner's device: serve's local listener forwards any local process as that node. The owner's phones and other computers get in as before, and paired devices are unaffected; a browser on the hub machine now pairs (#965).

  • The remote hub refuses wildcard and non-tailnet binds. swe remote serve --host=0.0.0.0 — or a LAN address, a link-local address, or a name that resolves to one — used to be taken verbatim; serve and serve --install now refuse it and name --unsafe-bind-any as the explicit override, matching the tailnet-only spec. Bind addresses may be loopback or a Tailscale address (100.64.0.0/10, fd7a:115c:a1e0::/48), by literal or by resolved name, and --install carries the flag into the service's command line when it was given.

The unauthenticated probe used to hand the machine's id and name, the swe version and the hub's uptime to the whole tailnet; it is a reachability check again. swe remote status now reads the machine row and version from the local machine's own files (it was the only consumer of those fields — the iOS client keeps an unused status() method, and swe remote setup only checks whether the route answers).

  • POST /v1/pair is rate-limited. Token exchanges get the same 5-per-10-minutes per-source-IP cap as /v1/pair/request, counted in a budget of their own and checked before the tailscale whois fork — a flood can't turn into subprocess churn.

  • The unauthenticated routes answer only Host names the hub serves. A plain loopback bind now records 127.0.0.1, localhost and [::1] (with the bound port) as its Host values — where previously the DNS-rebinding check had nothing to compare against — and a loopback bind behind tailscale serve keeps them alongside the public URL's name.   • iOS: the App Transport Security exception is scoped. The blanket NSAllowsArbitraryLoads is gone. *.ts.net (MagicDNS hub names) gets an insecure-HTTP exception, and NSAllowsLocalNetworking covers the unqualified or .local names and IP literals — including Tailscale CGNAT addresses — a hub address can take; arbitrary domains are back under full ATS.

The notifier now starts only when the config can actually post, and unsubscribes rather than leaving the queue behind.

The Allow/Deny/Always buttons used to send Authorization: Bearer <cred> for the ntfy-actions device row — a full-power credential good for every attached session — through the ntfy topic, where the host (and ntfy.sh's relay for iOS delivery) could read it.   • Quiver switches pages at once. Clicking a sidebar row or pressing ⌘1 to ⌘9 used to keep the old page up for 70 to 460 ms while the new page's rows were laid out. The new page's header now draws in the first frame (17 to 49 ms) and its content joins on the next run-loop turn.

  • swe session lists OpenCode sessions again. opencode 2.x turned its workspace table into provider bindings with no directory column, so the session query's workspace join failed with "no such column: w.directory" and every OpenCode row silently vanished. The query now checks workspace's columns first and joins it only as a path fallback when directory is there (older opencode, Kilo today).

  • Quiver opens the Sessions page faster. On a 2,450-session history a switch to Sessions held the main thread for about 155 ms; it now takes about 90 ms. The page used to filter every session several times per redraw and reread the ledger on every visit. It now keeps the filtered list, totals, day groups and filter choices until the sessions or filters change, and rereads usage only when the ledger changed.

  • Phone sends return immediately instead of hanging for the turn. POST /v1/sessions/{key}/message now answers 202 and runs the send on a per-session worker: queue mode waits for the session to go idle (up to 30 min) before injecting, steer writes at once, and the outcome lands as a command.result event carrying the caller's client_id. The PWA draws an optimistic bubble, keeps the composer visible (disabled) on observed sessions, and treats queued attaches as success. Attaching a claude session with no tmux on PATH now resolves to the headless channel instead of failing.

  • A board load no longer crashes the app on the GitHub pages. The Pages surface's persist closure — a literal formed on the main actor and handed to quiver.gh-history — inherited @MainActor isolation, and the runtime's queue assert trapped the moment the write queue called it. Repos with a Pages site hit it on their first board refresh. The persist parameters are @Sendable now, which keeps the closures nonisolated so the write queue can run them.

  • Resumed Codex threads are one session again. Every codex resume writes another rollout-<iso>-<thread>_<rollout>.jsonl, and the parser keyed each file on the trailing uuid — the resume's own rollout id, which the session index, the thread store and codex resume have never heard of. The thread uuid is the first one, so swe session now folds every resume into the thread's single row (the newest file stands for it), emits a resume hint codex resume can resolve, and finds the thread's real name. Index records written after the rollout's own timestamp no longer feed the rename check, and a resume that only re-states the live name can't stretch its rename window — resumes stopped reading as renames.

  • Quiver's main window goes fullscreen. A SwiftUI Window scene marks its NSWindow .fullScreenNone, so Enter Full Screen stayed off the green button's tiles and ⌃⌘F even though the window resized. The scene's content now opts in with .windowFullScreenBehavior(.enabled).

  • Quiver's Pricing and Models pages open without the wait. Their per-model usage read now runs on its own read-only ledger connection, off the main thread, instead of queueing behind a log scan (up to 3s on a busy ledger). Pricing runs one load on open instead of three in a row. Models draws the benchmarks at once and shows a spinner in the token cells until usage lands, rather than "No usage in this period". Its row build matches every logged name through one parsed index instead of re-parsing the whole Artificial Analysis list per name, which froze the window for over a second.

  • Quiver's Pricing page lets you price harness-billed models. Rows Cursor or another harness bills itself (it logs a charge per request) now open the price form like any other. A saved price fills the rate columns and prices any harness that logs no charge; that harness's own logged charge still sets its spend, as the form and the row's hover text say. Such a row with no rates reads "Harness" instead of "Billed by harness", which overflowed the Source column onto the cache write rate.

  • "Open app" on the Accounts page now focuses the account's own running instance. Quiver tells desktop-app instances apart by their --user-data-dir argument, so opening the default account while another account's instance is running starts a new default instance (instead of bringing that account forward), and opening an account that is already running focuses it (instead of starting a second copy on the same data directory).

  • swe install no longer guesses npm package names. It used to run npm install -g <name> with a small lookup table, which installed strangers' packages (gemini, crush, kiro-cli are unrelated on npm) or names that do not exist (opencode, mistral-vibe, @cursor/agent). Now swe install <name> lists the harness's verified install command per package manager (brew, cask, npm, uv, nix, vendor script), swe install <name> --via=<method> runs one, --package=<pkg> installs an explicit npm package, --dry-run prints the command, and --json emits the whole table without running. Names with no known installer are refused instead of guessed.

  • Renaming a harness account on the Accounts page no longer rewrites harness.json. The name (say "Cortex" for your Cursor account) now lives in the app's own ~/.quiver/accounts/harness-names.json and shows in Accounts, the menu bar and widgets only, so the Harnesses page keeps the harness's display name. The card's Open app/Terminal buttons are icons now.

  • A fresh Linux + Nix install bootstraps cleanly. Six first-run bugs together made a new machine look broken: any invocation — even a failed unknown command — created ~/.quiver/config/harness.json before it was asked for anything (a read now stays a read; save_registry is the one scaffolder), swe init skipped harnesses that had never run yet because a config dir was the only install evidence (a binary on PATH counts now, so Nix/uv installs like crush get their ~/.config/crush links, hooks included), swe doctor reported npm's global bin as the bare prefix when <prefix>/bin did not exist yet (the POSIX convention is the answer, unconditionally), swe list and swe check disagreed about the same registry because archived rows counted in one and vanished in the other (both now print the active count plus the shelved one, and an empty registry is a deliberate empty state instead of a header over 0/0), and swe discover --apply-all archived a home-scan find like hermes even when its binary probed a live version (the probe result, not the source, decides now; a find the confidence floor refuses is named with its remedy instead of silently dropped). Old seeded registry rows are left alone on upgrade — nothing in the file tells them from hand-authored ones, so deleting them could erase real entries; swe discover --apply-all after a swe remove remains the way to reset them.

  • Setup and provider fixes. swe setup stops the wizard at Ctrl-D (exit 130) instead of marking every remaining stage failed and exiting 0; swe setup --apply --json reports a failed apply step inside the applied.errors list and still emits its JSON envelope, so a run that half-applied no longer reads as success to the app. A failed instructions preview (instructions.error) exits 1 with a stderr line instead of looking like a clean run. swe providers messages name the real key store: a missing default store asks for one export NAME=<key> line per provider rather than a file-per-provider directory, and swe providers remove names the export line it left alone — the one the file actually holds, or every accepted name. swe providers add refuses a flag token as the provider name, and a providers.json entry that is not an object (or a _removed list holding non-strings) raises CorruptConfigurationError naming the row instead of crashing mid-merge.

1.0.0 - 2026-10-13

First stable release. swe and the Quiver macOS app share one data model under ~/.quiver, every --json command uses the {schema, data} envelope, and the design is documented under docs/: data model, app architecture, backend architecture, JSON contracts and testing.

Highlights since 0.2.10: Cursor's Grok Bot allowance, harness display names and primary colours, Devin quota handling, and in the app: per-account menu bar and widget projections with live previews, Compute trends, plugin and skill editing, MCP Local/Remote groups, collapsed service status cards, API key checks and editing, a cached and source-isolated Overview, and four audits (databases and caches, app structure and contracts, swe controller / service / model layering, tests with an 84% coverage floor).

Added

  • Cursor's Grok Bot allowance shows with its other limits. Cursor gives Grok Bot its own weekly allowance, apart from the billing cycle. swe list --usage --json now lists it as a grok_bot window on Cursor (used percent, reset time, a week long), read with the same Cursor login from DashboardService/GetSandUsageStatus on api2.cursor.sh. It is never the headline figure, and a seat on a pooled enterprise allowance or with no included Grok Bot limit gets no window. The call is optional like the plan and hard-limit ones: a failure leaves the reading as it was. Those optional calls now get 3 seconds instead of 1.2, since Grok Bot's host needs a connection of its own. The macOS app labels the window "Grok Bot".

  • Harnesses get a display name, editable with swe edit --display-name. A harness is keyed by its registry name and launched by its command (cursor runs cursor-agent), which is no way to label it in the app. harness.json entries now take an optional display_name ("Cursor", "Qwen Code"); absent or empty means unset. swe edit <name|alias> --display-name="Qwen Code" sets it (whitespace is trimmed) and --display-name= clears it; --display_name= and --set=display_name=... work too, and the interactive editor lists it as "display name". swe list --json rows carry display_name next to name (null when unset), swe edit --json reports "display_name" in changes, and swe info shows it when set. Nothing else changes: the swe list table keeps its columns, and a harness without a display name prints exactly as before. Re-adding or reinstalling a harness (swe add, swe add -i, swe install) keeps the name you gave it.

Changed

  • The desktop widgets get their own sidebar page. "Menu bar and widgets" split in two: "Menu bar" keeps the status item and popup settings and previews, and a new "Widgets" page lists the four widget kinds with the same underline tabs, previews and per-widget settings. The stored tab settings keep working; a leftover "widgets" selection on the Menu bar page falls back to the first tab.

  • The discover and setup commands emit the standard JSON envelope. swe harness discover --json, swe mcp discover --json, swe skills discover --json and swe setup --json used to print bare json.dumps output. They now emit the same {schema: 1, data: ...} document as every other --json command: discovery rows live under data.findings, and the setup preview under data.harness / data.mcp / data.skills. An --apply run adds an applied object inside the same data, so a --json --apply invocation prints one document instead of two.

Fixed

  • swe list --usage --json served an hour-old limit reading instead of a fresh one. Piped output gave each provider's fetch a 2 second cap, and a fresh swe process (which is how the macOS app reads limits) often needs longer for its first Cursor or Devin request, so it fell back to the last cached reading, up to 24 hours old. The app then showed "Fetched 1h ago, couldn't refresh". --json now waits up to the same 25 seconds an interactive terminal gets; the piped table keeps the short cap.

  • swe skills --json listed a hub plugin's skills from Claude's stale cache. Claude Code runs a plugin from a directory marketplace (every one in ~/.quiver/plugins) straight from the marketplace's folder, so a skill added to the source loads at once while the copy under ~/.claude/plugins/cache keeps the skills it had at install time. The listing read that copy, so a new skill was missing from it and from the app's Skills page, and a deleted one lingered. Such a plugin's skills are now read from <marketplace folder>/<source path in marketplace.json>/skills, and its cached versions are skipped, so no skill appears twice. Plugins Claude fetched (github, git, a URL) still run from the cache and are listed from there.

  • A broken config file no longer corrupts --json output. When a --json command hit an unreadable config (a malformed harness.json, say), the error went to stdout, where the app expects only JSON. It now goes to stderr for every --json command; without --json nothing changes.

  • swe find plugins flagged Claude Code plugins as out of date when they weren't. Claude Code reads a directory-marketplace plugin straight from its folder, so the copy under ~/.claude/plugins/cache is a leftover it never loads, and claude plugin update reports nothing to update. Comparing against that copy raised "N files differ" findings no fix could clear. Claude is no longer checked for stale copies; Codex, which runs its own copy, still is.

  • swe find plugins kept calling a Codex plugin stale after its fix ran. Codex follows no symlink when it copies a plugin, so a source whose .codex-plugin, .cursor-plugin or .factory-plugin was a symlink never matched its copy, and codex plugin remove && add changed nothing. The source is now compared the way Codex copies it, without its symlinks. A symlinked .codex-plugin is reported as a new kind, linked-manifest: Codex skips it and installs a manifest it generates itself, with no version (the copy shows up as local). Its fix replaces the link with a real copy of its target (copied beside the link first, then swapped in, so a failed copy leaves the link and its finding), and the next run offers the reinstall. The app shows it as "Linked manifest".

  • swe skills unlink ~/.x/skills unlinked the wrong thing. A path to a linked harness root resolved to the shared tree it points at, so the command tried to unlink shared and refused. A symlink given by path is now the root it names. This bit every harness swe skills has no label for (claude-work, opencode, droid, hermes, …).

  • swe init no longer registers and links every app with a skills/ folder. A non-terminal run (a nix rebuild's activation script, say) used to register each unknown ~/.<name>/skills as a harness and link it to the shared tree, so a token usage tracker's cache folder and a browser's skills folder both ended up as "harnesses". Now a new folder is linked only once someone ticks it: a non-terminal run leaves it alone and reports it as skipped, a cancelled picker links nothing, and the picker pre-ticks only folders whose owner has a command on PATH or a catalog entry. Aside, Pinokio, TokenTracker and Ollama are named in NOT_HARNESSES and never offered or linked; an active registry entry under the same name still wins. --yes still takes everything.

  • swe harness discover --apply NAME… and --pick. Registering was all-or-nothing by confidence tier (--apply or --apply-all). Naming findings now registers just those, at any confidence, and --pick opens a multiselect in a terminal with only catalog matches ticked. The home scan skips the NOT_HARNESSES apps too.

  • Ollama is out of the harness catalog. It was listed "so discovery names it", but catalog matches are exactly what discover --apply registers, so a local model runtime kept landing in harness.json. It is now in the PATH scan's exclude list instead, and gone from the alias help.

  • Claude no longer cries re-login on a self-healing token. An expired access token beside a refreshToken is a live login — Claude Code refreshes transparently on its next call — so the fetcher now serves the last reading from claude's own ≤24h cache instead of the red re-login, and a re-login marker in the shared cache is re-derived on sight rather than replayed for the TTL. The label is kept only for an expired token with no refreshToken, the case that genuinely needs claude auth login. Cache ages are honest now too: each provider's reading carries its own updated_at, a re-served stale reading keeps its real fetch time, and freshness is judged per provider — so a persistent refetch on one provider (the re-derived re-login) can no longer rewrite the envelope and keep every other provider's cached value alive forever.

  • swe providers add no longer erases removal tombstones. add saved a registry loaded without the _removed bookkeeping list, silently dropping every recorded removal — previously-removed default providers all came back on the next load. add now preserves _removed, lifts only the re-added provider's own tombstone, seeds a re-added builtin's default fields instead of persisting a bare record, and resolves aliases to the canonical slug instead of forking a duplicate entry. On the codex side, split_codex_toml now folds stray [mcp_servers*] tables found later in config.toml into the region (TOML allows them anywhere) instead of writing them twice on save — an invalid duplicate-table file — and _toml_value/render_codex_server handle datetime/date/time values tomllib produces instead of crashing or silently dropping the key.

  • Every subcommand now answers --help. swe report followup --help, followup <action> --help, report followups --help, and report warnings --help used to error out ("Unknown follow-up action", a bogus usage line, or a manifest-suffix complaint) — or worse, followup add --help recorded a follow-up literally named "--help". swe providers remove --help reported a missing provider named "--help", swe session help and swe models help were rejected as unknown arguments, and swe providers --help printed the short summary whose last line pointed back at swe providers --help itself — it now reaches the providers group's own detailed help.

  • Untrusted strings can no longer drive the terminal. Session titles, transcript text, file previews, directory names, and MCP server names all originate outside quiver, and a crafted value carrying an OSC-8 hyperlink, an OSC-52 clipboard write, a cursor-moving CSI, or a bare BEL/CR previously printed verbatim — inside a table cell, a picker row, or a find preview it could paint itself, open a link, or rewrite rows. A new console.sanitize removes every escape class (OSC through BEL/ST/end-of-string, CSI including private modes, charset and two-byte escapes, lone ESC) and maps C0/C1 controls to spaces (sanitize_document keeps \n/\t for transcript text, turns \r into a newline, and deletes other controls so a byte inside a credential cannot split it before redaction). Applied at the render boundary: table text/path/list cells, _display_title, the agent column, picker preview sources and labels, the checklist and tri-state labels, find-browser labels/details/preview rows, tree and path printing in swe find, and MCP name/label display. strip_ansi widened to match the same escape classes so width math is right on hostile input, while preformatted cells remain an intentional trusted styling path. Transcript text is cleaned inside _clean_text, so reports and previews share the guarantee.

  • swe mcp sync preserves the target's own format keys on overwrite. Syncing over an existing entry dropped everything outside the canonical shape: an opencode server marked enabled: false was silently re-enabled, a droid type: sse became http, and claude's disabled/autoApprove vanished. Overwrites now merge the target's extension keys back over the emitted fields. Also in the MCP domain: redact() now swaps long (16+ char) credentials wherever they appear in a string, so a ?key=TOKEN URL resolved into a harness config redacts back to ${NAME} in the hub instead of persisting plaintext (resolve() always substituted mid-string; redact never did); server_summary redacts before printing so mcp sync's conflict display and mcp doctor no longer echo credential-bearing URLs; and an unverified registry name containing /, \, or .. gets no optimistic ~/.<name>/mcp.json path — mcp sync/list/status/diff/validate on it exit cleanly instead of a write outside the home directory or a KeyError/AttributeError crash.

  • Terminal widgets restore the terminal on every exit path. The session picker, checklist, tri-state picker, and find browser each hand-rolled raw mode and cleanup, so a fatal signal (or an exception between tty.setraw and restore) left the terminal raw with mouse tracking on. A shared keys.raw_terminal now owns setup, mouse-off, cursor-show, and termios restore, plus signal handlers for SIGHUP/INT/QUIT/TERM that clean up through the raw fd before re-raising. keys.read_key polls before each byte of an escape sequence so a truncated Esc [ can no longer block forever, and unknown sequences are ignored instead of cancelling the widget. Rows are padded by terminal cell width (console.cellpad), fixing misaligned columns under CJK text, combining marks, and wide emoji. swe session and friends also read CR, LF, and CRLF correctly from pipes now: a piped a\r\nb\r\n used to eat every second answer, and piped input no longer echoes back into the output.

  • Malformed config files can no longer be wiped by a write. swe mcp sync/discover --apply/edit treated an unparseable harness config as {} and then rewrote it holding only the MCP slice — for claude that meant ~/.claude.json's OAuth tokens, projects, and settings destroyed. load_json now raises CorruptConfigurationError on malformed or non-object content; read paths (mcp list/status/diff/discover, get_hub_servers) warn and degrade while every write path refuses. The same guard covers quiver's own files: harness.json and providers.json raise a clean error on a corrupt file instead of a raw traceback or a silent overwrite-with-defaults (the providers "corrupt reads as read-only" path was fake — the seed branch overwrote it), skill_catalogs.json refuses to save over a malformed file, and both registries plus the catalog file now write atomically via atomic_write_text so a crash mid-write can't leave a truncated file that bricks the next run. Non-object JSON ([1] as mcp.json) warns instead of crashing with AttributeError, and the top-level swe, swe mcp, and swe providers entry points all turn ConfigurationError into a red message + exit 1.

  • One malformed session record no longer poisons swe session. json.loads accepts NaN/Infinity literals and sqlite REAL columns can hold ±Inf — a cline meta file with "started_at": NaN killed the whole listing at int(diff / 86400). Session now coerces timestamp (non-finite or unparseable → 0.0), drops non-string path values to missing (a json number would otherwise survive as a relative path a --here filter could match), and stringifies agent/title/session_id/tool_name at construction, so every engine and the session-cache reader share the guarantee. parse_iso_ts rejects non-finite inputs too, and absurd --days=/--end= values (--days=1000000, --end 9999-12-31) now hit the same clean error path as other bad dates instead of an uncaught OverflowError.

  • Completion tables drifted from dispatch. swe <TAB> never offered find or discover and listed harness twice; list completed no --usage/--links; session lacked --grep; report lacked --search/--session-arg/--writer-arg; and no subcommand completed under mcp, find, skills, or providers. All tables are rebuilt: nested flag sets (swe mcp sync --<TAB>, swe skills move --<TAB>, swe report followups --<TAB>), second-level subcommands for mcp/find/skills/providers/session, third-level actions (report followup, skills catalog, config setup), tool names for mcp sync/diff (excluding ones already typed, aliases included), provider names for providers info/remove, and server names for mcp edit <tool>. swe doctor now checks the completion tables against dispatch so the drift cannot silently regrow.

  • Audit leftovers: hidden flag, dead flag, 404 help topics, inconsistent exits. swe mcp sync --prune worked but was missing from swe mcp sync help; it is documented now. swe skills help tree/scope/scopes 404'd on topics swe help skills advertises — they now print a help page explaining the swe find skills -r hand-off. --json on swe skills link/unlink/move was parsed and ignored; it now prints a machine-readable result, and the shared parser rejects flags that do not belong to the subcommand (--mkdir on link/move, --force on unlink, any unknown flag). swe report daily --help and bare swe report/swe report help print the report help and exit 0 instead of erroring, matching mcp/providers/skills/config. swe session use abc/use say "Usage: swe session use " instead of "Unknown argument". swe mcp ls now aliases mcp list. Help texts also fixed: --apply-all adds every match (not "high + medium"), -n documented as --check/--dry-run on init/install, and a note marks that -n means fetch-fresh on swe list instead.

  • swe mcp sync picker uses the shared checklist widget. mcp/cli.py carried its own getch() + escape-sequence parser (interactive_select), which blocked forever on a bare Esc and skipped the repo's key-handling rules. Both pickers (server selection, conflict overwrite) now call multiselect.multiselect, which cancels cleanly on q/Esc/Ctrl-C, scrolls with the wheel, and restores the terminal on every exit path.   • v0.2.8 could not start on Python 3.10 or 3.11. swe find's summary line used a nested f-string with implicit concatenation inside a replacement field, which is PEP 701 and valid only on 3.12+. It parsed fine locally and raised SyntaxError on import for anyone at the declared floor, taking the whole CLI down. Anyone on v0.2.8 should upgrade.

Added

  • A syntax-floor test. Compiles every file in src/ with an interpreter at or below requires-python, so this class of bug fails locally instead of in the release. Two earlier attempts at this guard silently passed: ast.parse(feature_version=...) accepts the syntax even at (3, 8), and py_compile with cfile='/dev/null' raises FileExistsError before it reaches the parser. It uses the builtin compile() now, and is verified against the actual v0.2.8 defect.

0.2.8 - 2026-08-20

Added

  • swe find. The read-only counterpart to swe init: where the shared assets live and what links to them. swe find amd for AGENTS.md, swe find skills for skills and plugins, bare swe find for both.
    • --root / -r scans from wherever ~/.quiver lives; the default scans the current directory. Both recursive.
    • --scope=global|local|all, default global. A file is global when it sits directly in a harness root (~/.<tool>/, ~/.config/<tool>/) or is symlinked to the shared copy. On a real machine that is 10 files out of 112.
    • Files nested deeper inside a harness directory (plugin caches, vendored repos, editor extensions) are counted in every view and listed under --scope=all, so an unexplained jump stays visible.

Removed

  • The ~/.agents legacy alias. The old shared skills root, plus the 74 per-skill symlinks six harnesses kept pointing into it (42 of which were already broken). Those roots now link to ~/.quiver/skills directly.

  • swe mcp discover --prune. Removes hub servers that no harness configures any more. Without it they are reported and left in place.

  • Credential indirection for the MCP hub. ~/.quiver/mcp.json now stores ${NAME} references; values live in ~/.quiver/secrets/.api_keys (mode 600, gitignored), so the hub itself is safe to commit. swe mcp sync resolves on emit rather than relying on the environment, because Claude, Cursor and Antigravity launch from the Dock and never read a shell profile. swe mcp discover redacts on ingest, so reading a harness config cannot write plaintext back into the hub. Names absent from the store are reported and left literal rather than blanked, since an empty credential authenticates as nobody and looks like a server bug.

  • --only and --except accept globs on swe mcp sync. Server names carry a category prefix, so --only=dv__* takes a category and --only='*__*' takes every categorised server, which is also the line between servers worth sharing and servers bound to one tool's own binary. A pattern that matches nothing is now named instead of failing silently, so a typo no longer looks identical to an empty result.

Changed

  • swe mcp discover --apply now merges three ways. It previously skipped anything already in the hub by name, so a token rotated in a harness config never reached the hub and a later sync quiver --all pushed the stale value back out over it. It now adds new servers, updates ones a harness has edited, and reports servers the hub still lists that no harness configures.

  • MCP moved under ~/.quiver. The server checkouts moved from ~/.mcp-servers to ~/.quiver/mcp/servers (2.7 GB, instant rename, symlink left behind), and all 79 absolute path references across 5 harness configs were rewritten. mcp.json now sits at ~/.quiver/mcp.json rather than in config/: it is the control plane for a subsystem, not one more settings file. mcp/servers/ is gitignored, since it is 21 nested git repos and mcp.json records how to rebuild it.

Existing outage caching keeps the last successful reading visible when Antigravity is closed.

  • Security: SSRF / LFI fix in swe mcp <tool> status health check. src/swe/mcp/cli.py::check_server_health now validates that any URL it fetches via urllib.request.urlopen strictly starts with http:// or https:// (case-insensitive) before issuing the HEAD request. Without this guard, an attacker who can write a configuration file can pass a file:///etc/passwd URL and have Python happily open and stat a local file as a "health check" — turning a LFI probe into a single endpoint. The check applies to both http server types (direct URL field) and wrapped server types (URL inside args). (PR #2.)

  • Security: Bandit B324 / FIPS-compliant hashlib.md5 in Kimi parser. src/swe/sessions/parsers.py::parse_kimi::load_hash_map now passes usedforsecurity=False to the single hashlib.md5(p.encode()) call — the hash is used purely to build a stable map-key from a path string, never for authentication or integrity. This silences the Bandit B324 rule (weak hash for security-related use) and is required for FIPS-mode Python builds. usedforsecurity was added in Python 3.9; the project's requires-python = ">=3.10" covers it natively. (PR #17.)

  • Performance: memoize os.path.realpath in the session aggregator's cwd filter loop. src/swe/sessions/aggregator.py::get_all_sessions used to issue an os.path.realpath syscall on every session's path when filtering by cwd — O(N) disk stats for what is functionally O(U) unique paths (most sessions share a project root, and a project tree has a small number of unique realpaths). Now caches realpath results in a dict[str, str] local to the loop, and hoists target_path + os.sep out of the loop to avoid redundant string concatenation. (PR #1.)

  • Performance: replace os.listdir with os.scandir across all session engines. os.listdir() + os.path.isdir() / os.path.isfile() chains issue a separate stat() syscall per entry to compute the file kind, multiplying latency in deeply nested agent session trees. os.scandir() returns DirEntry objects whose is_dir() / is_file() / stat() reuse cached metadata from the directory iteration itself, collapsing the N+ syscalls into one. Touched files: src/swe/sessions/parsers.py (parse_cursor, parse_antigravity), src/swe/sessions/engines/jsonl_engine.py (5 sites), src/swe/sessions/engines/json_engine.py (2 sites — nested parent+session-dir loops), src/swe/sessions/models_analytics.py (3 sites — claude + freebuff paths). Every site is wrapped in with os.scandir(...) as <var>_it: so the directory FD is released on scope exit (caught and fixed during triage — bare iterators leaked FDs on early-break / exception paths). (PR #18.)

Starred rows pass accent="neon" (rows 1–3 are prefix-pinned); the RATE column uses trust_cell_width=True so RateLimitInfo.format_column() controls its own width without Table re-padding. 12 new tests in tests/test_harness_commands.py pin the migrated layout: header column order, separator-width alignment with header, starred vs. unstarred row NAME alignment at the same visible column index (the whole reason for the migration), sentinel _text-strip-ANSI safety, three-state SESS coloring, green/red INST glyphs, sort order preservation, and tag-filter behavior.

Changed

  • swe mcp list / status / validate / doctor hide unverified harnesses whose config file does not exist yet, keeping the matrix readable. Name a harness explicitly to inspect it.
  • swe mcp sync <src> --all broadcasts to verified peers plus unverified tools that already have a config file; it no longer risks creating many new files in one shot.
  • swe list --refresh now also invalidates the rate limits cache (in addition to the session cache).

Fixed

  • mcp.json's updated timestamp never changed. It used setdefault, so only the first write was ever stamped; the file claimed to be hours older than its contents.

  • Deleted 331 KB of dead source from the config directory. mcp.py, mcp_formats.py, mcp_server.py, tests/, __pycache__/ and archive/swe.py were left over from the single-file era. Nothing referenced them: not the package, not any MCP config, not the shell profiles.

  • Rate-limit cache never covered providers that report nothing. A fetcher returning no data was absent from the cache, so it counted as a miss and re-ran on every invocation. For antigravity that meant spawning two subprocesses per swe list, 70ms even on a warm cache. Negative results are now remembered for the same TTL, taking the warm path to 0.1ms. Fetchers that hit the deadline are still retried rather than recorded as empty.

  • Antigravity 2.3.x quota discovery now carries the per-language-server --csrf_token into the loopback RetrieveUserQuotaSummary request. Quiver previously found the correct listeners but received HTTP 401 responses, so the RATE cell stayed blank even when Antigravity was running.

  • Claude Code usage is fetched again for paid subscriptions instead of always rendering the temporary no-sub placeholder. The RATE cell shows the most utilized 5-hour, 7-day, or 7-day Sonnet window, treats Anthropic's utilization value as an existing 0-100 percentage, and retains the last successful reading during a 429 Retry-After cooldown. HTTP diagnostics now also survive the macOS certificate fallback path. Expired, non-refreshable Claude credentials now render re-login instead of a blank RATE cell.

  • Forced rate-limit refreshes retain each provider's last successful reading for up to 24 hours when its network request fails or misses the shared deadline. A slow refresh can no longer replace the complete RATE cache with an empty snapshot; per-provider timestamps prevent stale readings from being renewed merely because another provider succeeded.

  • Droid now displays an exhausted monthly or weekly quota when that longer window is blocking usage, instead of always showing the available 5h quota. When no window is exhausted, 5h remains the default. The reset countdown now corresponds to the displayed window. Factory's current usedPercent field is treated as usage directly; the previous inversion incorrectly turned a live 100% weekly lock into 0% usage.

  • Droid rate-limit lookups now have a two-second wall-clock deadline, so a stalled DNS lookup or Factory API request cannot freeze swe list. Slow or unavailable responses degrade to an empty RATE value for that cache refresh. All provider lookups now run concurrently under the same two-second overall budget, and empty results are cached to avoid repeated waits during outages.

  • Rate-limit fetchers now print actionable stderr hints on HTTP errors: 401 (stale token — re-auth required), 429 (parsed Retry-After countdown so the user knows exactly when to retry), 403/404 (the URL or x-factory-client header may need updating), and 5xx (upstream or network error). Previously, an unreachable endpoint silently produced a — in the RATE column with no signal as to why; running swe list --refresh 2>&1 now surfaces the root cause. The Claude fetcher's hint for 401 includes the offending anthropic-beta value so the operator can rotate it in _BETA_VERSIONS. The Droid hint for 401 names the macOS Keychain label (Factory Safe Storage) plus the FACTORY_API_KEY env var override so the user has the exact commands to fix it. The _fetch_json helper's on_401 callback contract is preserved; an on_http_error callback is added as a new optional kwarg that defaults to None. Replaces the previous silent-degrade pattern in both harness/rate_limits.py -type fetcher wrappers.

  • Rate limit fetcher now retries with an unverified SSL context when the default certificate verification fails. This fixes SSL: CERTIFICATE_VERIFY_FAILED errors on macOS python.org builds (Python 3.12+ ships without system CA certificates until "Install Certificates.command" is run). The connection remains encrypted; only server-cert pinning is skipped as a fallback.

  • Fixed Python exception hierarchy bug in _fetch_json: URLError (a subclass of OSError) was being caught by the OSError handler before the dedicated URLError handler could trigger the SSL retry, making the fallback dead code. Subclasses must be caught before their base classes.

  • _parse_iso8601_to_epoch now correctly parses ISO 8601 timestamps with fractional seconds combined with a timezone offset (e.g. "2026-08-01T00:00:00.000Z", "...+00:00") on Python 3.10 — previously only Python 3.11+ accepted that combination. Without the fix, the parser silently returned 0.0 and the RATE column rendered — for the reset countdown.

  • Naïve ISO 8601 timestamps (e.g. "2026-08-01T00:00:00") are now explicitly treated as UTC. Previously, datetime.fromisoformat(...).timestamp() silently applied local time on naïve strings, producing a reset countdown that shifted with the user's TZ. Codex's parser was refactored to use the shared helper, eliminating a duplicated buggy inline parser.

  • _fetch_codex now uses not isinstance(reset_at, bool) as a guard inside the numeric reset_at branch. Without it, a pathological reset_at: true payload would silently become 1.0 (since bool subclasses int in Python). Same fix applied conceptually to _derive_copilot_fields for percent_remaining and entitlement.

  • Test fixture isolation: test_fetch_codex_reset_at_type_dispatch now uses copy.deepcopy on the shared _SAMPLE_RESPONSE fixture before mutating nested keys. A previous shallow-copy version leaked the per-subtest reset_at mutation into _SAMPLE_RESPONSE, which corrupted test_fetch_codex_success when the suite ran in alphabetical order.
